# Awesome Claude Code Subagents


## これは何ですか？

このリポジトリは、Claude Codeサブエージェントの決定版コレクションです。特定の開発タスク向けに設計された専門的なAIエージェントを集めています。各サブエージェントは：

- **本番環境対応**: 実際のシナリオでテスト済み
- **ベストプラクティス準拠**: 業界標準とパターンに従っています
- **最適化されたツールアクセス**: 各エージェントは役割に応じたツール権限を持っています
- **継続的なメンテナンス**: 新機能の定期的な更新
- **コミュニティ駆動**: 貢献と改善にオープン

## クイックスタート

1. カテゴリを閲覧して必要なサブエージェントを見つける
2. サブエージェントの定義をコピー
3. Claude Codeで使用するか、ワークフローに統合
4. プロジェクトの要件に応じてカスタマイズ

## 🤖 サブエージェントを理解する

サブエージェントは、タスク固有の専門知識を提供することでClaude Codeの機能を強化する専門AIアシスタントです。特定の種類の作業に遭遇したときにClaude Codeが呼び出せる専用ヘルパーとして機能します。

### サブエージェントの特別な点は？

**独立したコンテキストウィンドウ**
すべてのサブエージェントは独自の分離されたコンテキスト空間で動作し、異なるタスク間のクロスコンタミネーションを防ぎ、メインの会話スレッドの明確さを維持します。

**ドメイン固有のインテリジェンス**
サブエージェントは専門分野に合わせて慎重に作成された指示を備えており、専門タスクで優れたパフォーマンスを発揮します。

**プロジェクト間で共有**
サブエージェントを作成した後、様々なプロジェクトで利用したり、チームメンバー間で配布して一貫した開発プラクティスを確保できます。

**きめ細かいツール権限**
各サブエージェントに特定のツールアクセス権を設定でき、異なるタスクタイプでどの機能が利用可能かをきめ細かく制御できます。

### コアアドバンテージ

- **メモリ効率**: 分離されたコンテキストにより、メインの会話がタスク固有の詳細で乱雑になるのを防ぎます
- **精度の向上**: 専門的なプロンプトと設定により、特定のドメインでより良い結果が得られます
- **ワークフローの一貫性**: チーム全体でのサブエージェント共有により、一般的なタスクへの統一されたアプローチを確保します
- **セキュリティ制御**: サブエージェントのタイプと目的に基づいてツールアクセスを制限できます

### サブエージェントを始める

**1. サブエージェントマネージャーにアクセス**
```bash
/agents
```

**2. サブエージェントを作成**
- プロジェクト固有またはグローバルサブエージェントを選択
- Claudeに初期バージョンを生成させ、ニーズに合わせて調整
- サブエージェントの目的とアクティベーショントリガーの詳細な説明を提供
- ツールアクセスを設定（空のままにするとすべての利用可能なツールを継承）
- 組み込みエディター（`e`を押す）を使用してシステムプロンプトをカスタマイズ

**3. デプロイと利用**
サブエージェントはすぐに利用可能になります。Claude Codeは適切な場合に自動的にそれを使用するか、明示的にヘルプを要求できます：
```
> code-reviewerサブエージェントに最新のコミットを分析させて
```

### サブエージェントの保存場所

| タイプ | パス | 利用可能範囲 | 優先度 |
|------|------|--------------|--------|
| プロジェクトサブエージェント | `.claude/agents/` | 現在のプロジェクトのみ | 高 |
| グローバルサブエージェント | `~/.claude/agents/` | すべてのプロジェクト | 低 |

注意: 名前が競合した場合、プロジェクト固有のサブエージェントがグローバルのものを上書きします。



## 🛠️ サブエージェントの使い方

### Claude Codeでのセットアップ
1. プロジェクト内の`.claude/agents/`にサブエージェントファイルを配置
2. Claude Codeが自動的にサブエージェントを検出してロード
3. 会話で自然に呼び出すか、Claudeにいつ使用するか判断させる

### 新しいサブエージェントの作成 - ステップバイステップ

**ステップ1: エージェントインターフェースを起動**
```bash
/agents
```

**ステップ2: 「新しいエージェントを作成」を選択**
- プロジェクトレベル（現在のプロジェクト）またはユーザーレベル（すべてのプロジェクト）のスコープを決定

**ステップ3: エージェントを設定**
- **推奨アプローチ**: Claudeに初期バージョンを作成させ、その後カスタマイズ
- エージェントの役割とアクティベーションシナリオの包括的な説明を記述
- 特定のツール権限を付与（または完全アクセスの場合は空白のまま）
- インターフェースを通じて利用可能なツールを閲覧して簡単に選択
- `e`を押してシステムプロンプトを直接編集し、高度なカスタマイズを行う

**ステップ4: 保存して使用開始**
- エージェントはすぐに使用可能
- Claudeは自動的に適切なタスクを委任
- または手動で呼び出す：
```
> code-reviewerエージェントにプルリクエストを確認させて
```

## 📖 サブエージェントの構造

各サブエージェントは標準化されたテンプレートに従っています：

```yaml
---
name: subagent-name
description: このエージェントがいつ呼び出されるべきか
tools: Read, Write, Edit, Bash, Glob, Grep
---

あなたは[役割の説明と専門領域]です...

[エージェント固有のチェックリスト、パターン、ガイドライン]...

## コミュニケーションプロトコル
エージェント間通信の仕様...

## 開発ワークフロー
構造化された実装フェーズ...
```

### ツール割り当ての哲学

各サブエージェントの`tools`フィールドは、役割に最適化されたClaude Code組み込みツールを指定します：
- **読み取り専用エージェント**（レビュアー、監査者）: `Read, Grep, Glob` - 変更せずに分析
- **リサーチエージェント**（アナリスト、研究者）: `Read, Grep, Glob, WebFetch, WebSearch` - 情報を収集
- **コードライター**（開発者、エンジニア）: `Read, Write, Edit, Bash, Glob, Grep` - 作成と実行
- **ドキュメンテーションエージェント**（ライター、ドキュメンター）: `Read, Write, Edit, Glob, Grep, WebFetch, WebSearch` - リサーチを含むドキュメント作成

各エージェントは必要最小限の権限を持っています。MCPサーバーや外部ツールを`tools`フィールドに追加してエージェントを拡張できます。
